# PayPilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship PayPilot, a supervised AI collections and payout agent on PayPal sandbox, as a hosted, demo-ready hackathon submission before **Thu Nov 12, 2026, 12:00 PT** (Fri Nov 13, 00:30 IST).

**Architecture:** One Next.js 15 (App Router) app on Render. Server-side `lib/` modules wrap the PayPal REST APIs (Invoicing v2, Payouts v1, Webhooks), a deterministic risk scorer and policy gate, and a Claude agent (Vercel AI SDK v4 plus the PayPal Agent Toolkit's read tools). Postgres on Neon holds what PayPal doesn't have: demo client history, risk, the approval queue, splits, rules and the activity log. PayPal stays the source of truth for invoice state. The UI polls JSON routes every 3s.

**Tech Stack:**
- Node 20 LTS, Next.js 15, React 19, TypeScript, Tailwind v4, shadcn/ui
- `ai@4` + `@ai-sdk/anthropic@1` (model `claude-sonnet-5-5`), `@paypal/agent-toolkit@1.11.0`, `zod@3`
- `drizzle-orm` + `@neondatabase/serverless`, `ag-grid-react@36` / `ag-grid-community@36` (Community, MIT), `recharts`, `swr`, `resend`
- Tests and scripts: `vitest`, `tsx`
- Hosting: Render Web Service. Database: Neon free tier.

**Spec:** `docs/superpowers/specs/2026-11-10-paypilot-design.md`

## Global Constraints

- Sandbox only: `PAYPAL_API_BASE=https://api-m.sandbox.paypal.com`. Never live credentials.
- Money is **integer cents** in DB and logic, USD only. It is converted to PayPal strings only via `centsToString` (Task 2).
- Pinned majors: `ai@4`, `@ai-sdk/anthropic@1`, `zod@3`, `@paypal/agent-toolkit@1.11.0`, `ag-grid-*@36` (Community features only), Next 15, Node 20.
- Tone bands: score `<40` → `gentle`, `40–69` → `friendly_firm`, `≥70` → `firm`.
- Default rules: `{ autoSendMaxAmountCents: 50000, autoSendMaxRisk: 40, autoSendTones: ['gentle'], autoSendInvoices: false }`.
- Every PayPal call hits the real sandbox. No mocked PayPal in the running app (mocks only in unit tests).
- Seeded client history is synthetic and shown in the UI with a **"Demo data"** badge.
- Every agent, rule, user and webhook action writes one `activity` row.
- All "now" logic uses `demoNow()` (Task 4), never `new Date()` directly.
- Repo is public with an MIT `LICENSE`. `.env` is never committed.
- Model ID comes from env `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`).

## Review Focus

1. **The same payment is reported twice** (PayPal webhook retry, or webhook + polling sync). Each collaborator must get **exactly one** payout. Covered by Task 5 `planPayouts` test, the Task 1 unique constraint, and the Task 6 manual "resend webhook" check.
2. **Approve is clicked twice, or clicked after the client already paid.** The reminder goes out once, or the action is skipped with "Invoice already paid". Covered by Task 5 `canExecute` tests and the Task 7 atomic claim plus double-curl check.
3. **Claude is down, slow, or returns junk.** The agent run still completes with deterministic scores and template drafts, labelled "template". Covered by the Task 9 fallback test.
4. **Splits add up to more than 100%, or cents don't divide evenly.** Payouts must never exceed what was received. Covered by Task 5 `computeSplits` tests and Task 14 server-side validation.
5. **A PayPal error mid-action** (422, `INSUFFICIENT_FUNDS`, timeout). The action becomes `failed` with a readable message and a Retry button; nothing crashes. Covered by the Task 2 `describePayPalError` test and Task 7 `retryAction`.
